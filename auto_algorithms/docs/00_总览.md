# 00 总览：自主生成算法库在做什么

## 问题

仓库里已有四个算法库和一个集成层，但"开发一个新算法"仍然是人工活：想清楚假设 → 从几个库里找组件 → 写适配代码 → 评估 → 写文档。
`autoalgo` 把这条链路做成管线，并强制要求**每个算法同时产出中文可解释性文档**。

## 一张图

```
                 ┌────────────── families.py（模板族：构造方式 + 搜索空间 + 文本骨架）
                 │
 panel ──► search/llm（提议参数）──► components.*（实例化新算法）──► evaluate（vs 基线）──► 选优
                                                                                      │
          generated/<algo_id>/{algorithm.py, <algo_id>.md, blueprint.json, evaluation.json} ◄── codegen + explain
                                                                                      │
          quantstack.core.registry（kind = autoalgo.<algo_id>）◄── registry.py ◄── index.json
```

## 术语

| 术语 | 含义 |
|---|---|
| 模板族 family | 一种新算法的"构造方式"：实现类 + 默认参数 + 搜索空间 + 假设 / 机制 / 风险文本。首批 7 个。 |
| 候选 candidate | 模板族的一组具体参数；由默认参数 + 提议器给出。 |
| 蓝图 blueprint | 选中候选的完整说明书（参数、组件、文本、血缘），代码与 md 都从它渲染。 |
| 评估报告 | 指标 + 基线 + 通过与否 + 中文结论。 |
| kind | quantstack 注册名：`autoalgo.<algo_id>` / `autoalgo.family.<family>` / `autoalgo.auto`。 |

## 五个库各贡献什么

- **factormine**：表达式求值、IC 评估、权重合成、GP 挖掘、算子注册入口。
- **crossquant**：Hurst/DFA、BOCPD、路径签名、分数阶差分、排列熵、Kalman、RMT 去噪、HRP、Kelly、LinUCB、Thompson、PID/LQR。
- **order_placement**：执行策略基类（计划曲线、追单 / 被动、簿记、§8 约定）、AC 轨迹、排队价值、8 种基础策略。
- **latency_routing**：延迟感知 SOR（作为路由叠加层的底层与基线）。
- **quantstack**：契约 / 协议、参考实现（基线与冷启动）、合成市场 + 撮合模拟器 + TCA（评估台）。

## 一句话结论

新算法 = 既有组件的新组合 + 搜索出的参数 + 用基线验证过的证据 + 一份说清楚"为什么 / 怎么做 / 什么时候会失效"的文档。
