# 03 可解释性文档规范

每个生成算法必须附带 `generated/<algo_id>/<algo_id>.md`，由 `autoalgo.explain.render_markdown(blueprint, report)` 渲染。章节固定，便于人工审阅与 agent 解析：

| 节 | 内容 | 数据来源 |
|---|---|---|
| 1 概述 | 设计假设一段话 + 评估结论（通过 / 未通过） | `blueprint.hypothesis`, `report.verdict` |
| 2 所处协议层与接口 | 协议、方法签名、输入输出、quantstack 注册名 | `blueprint.protocol`, `explain.PROTOCOL_DOC` |
| 3 设计动机与假设 | 成立前提（数据频率、样本量、平稳性…） | `blueprint.assumptions` |
| 4 组件来源 | 表：库 / 组件导入路径 / 在本算法中的作用；涉及库列表 | `blueprint.components`（来自 `catalog.components_for(family)`） |
| 5 算法流程与关键公式 | 分步机制 + 公式 | `blueprint.mechanism`, `family.formula` |
| 6 参数 | 表：取值 / 含义 / 搜索范围 | `blueprint.params / param_doc / search_space` |
| 7 评估结果 | 主目标与方向、相对基线改善、全部指标表（本算法 vs 各基线）、判定与通过条件、耗时 | `EvaluationReport` |
| 8 已知风险与失效条件 | 什么时候会失效、怎样缓解 | `blueprint.risks` |
| 9 接入方式 | 代码片段（`autoalgo.registry` 与 `build_sim_pipeline(kinds=...)`） | `codegen.usage_code` |
| 10 复现与血缘 | 生成器版本、提议器、模型与思考强度、seed、预算、候选列表（参数 / 得分 / 理由）、重新生成命令 | `blueprint.lineage` |

## 写作要求

- 中文；公式用反引号内的纯文本（避免渲染器差异）。
- 结论必须与 `evaluation.json` 一致（同一个对象渲染）；不得只写优点，第 8 节不可为空。
- 参数表必须覆盖 `params` 的每个键；没有搜索范围的参数标 "—"。
- "优于基线"与"通过"是两件事：通过条件由评估台定义并写在 notes；优于基线单独陈述。

## 新增模板族时

在 `families.py` 登记 `FamilySpec`，填满 `hypothesis / mechanism / assumptions / risks / param_doc / formula`，并在 `catalog.py` 的 `used_by` 里标注用到的组件 —— 第 4 节会自动生成。
