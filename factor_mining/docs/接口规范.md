# 接口规范：factormine 对外契约

因子库对下游（挂单策略库、路由延迟库、全栈 agent）只暴露两层接口。

## 1. 原生接口（`factormine.interface`）

```python
model = fm.AlphaModel(library, method="max_ir", horizon=1).fit(history_panel)
sig = model.signal(panel)                    # 最新时刻的 AlphaSignal
w = sig.target_weights(gross=1.0, mode="long_short", max_weight=0.03)
json.dumps(sig.to_dict())                    # schema = "factormine.signal/1"
```

`AlphaSignal` 字段：

| 字段 | 含义 | 下游用途 |
|---|---|---|
| `timestamp` | 信号时刻 | — |
| `scores` | 横截面 z-score（资产 → 分数） | 组合层加权 |
| `expected_return` | Grinold：IC × σ × z（horizon 期收益） | 执行层的 alpha 与成本权衡 |
| `ic` | 合成信号样本内 RankIC | 置信度 |
| `horizon` | 预测期（bar） | — |
| `half_life` | 信号半衰期（bar），由边际 IC 衰减曲线插值得到 | 执行节奏 |
| `urgency` | 0~1，= 1/半衰期 | 挂单激进程度、路由延迟预算 |

`target_weights` 在多空模式下两侧各分一半杠杆、分别截断，所以净敞口为 0，单票权重不超过上限。

## 2. 全栈系统契约（`factormine.integration`，对应 `quantstack.contracts`）

```python
import sys; sys.path += ["/mnt/project-files/factor_mining", "/mnt/project-files/trading_system"]
import factormine as fm

miner = fm.make_miner(methods=("gp", "rl", "llm"), seed=0, llm=fm.AnthropicClient())
specs = miner.mine(panel, budget=100)                # -> list[FactorSpec]
report = miner.evaluate(specs[0], panel, sample="oos")  # -> FactorReport

model = fm.make_alpha_model(library=miner.library, method="max_ir")
model.fit(panel)
batch = model.predict(panel, as_of=ts)               # -> SignalBatch（as_of 之后的数据会被截掉）
model.describe()
```

- 能 import `quantstack.contracts` 时返回其 dataclass，否则返回字段相同的 dict。
- `AlphaSignal.expected_return_bps = IC × σ × z × 1e4`；`confidence = clip(|IC|/0.1) × min(|z|/2, 1)`；
  `metadata` 带 `half_life_bars`、`urgency`、`ic`；`factor_exposures` 是各因子当期的横截面 z。
- `FactorReport.ic_ir` 是单期 IR（未年化），年化值在 `extra` 中。
- `budget` 控制计算量：GP 种群 = max(20, budget)，代数 = max(2, budget//20)，RL 轮数 = max(2, budget//10)，LLM 轮数 = max(1, budget//50)。

## 3. 数据格式

`Panel = dict[str, DataFrame]`，index 为时间，columns 为资产，字段名小写：open/high/low/close/volume/vwap/returns。
用 `fm.validate_panel` 对齐并补齐 vwap/returns。全栈系统也使用同一格式。

## 4. 扩展点

| 想做的事 | 入口 |
|---|---|
| 新增算子（如物理/控制方向的卡尔曼滤波、Hurst 指数） | `fm.register(name, func, arity, category, doc)`，GP/RL/LLM 会自动可用 |
| 接入别的 LLM | 实现 `complete(system, prompt) -> str` |
| 换成 PyTorch 深度模型 | 实现 `fit(feats, fwd, rows)` / `predict(feats)` |
| 新的挖掘算法 | 往同一个 `FactorPool` 调用 `try_add(expr, source)` 即可与其它算法协同 |
